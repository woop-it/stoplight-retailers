# Changelog 1.17 -> 2.0


Changes between version 1.17 and version 2.0 are listed here.
Versionning is now in the path with /v2 prefix

- URL-based Versioning: API versioning is now managed directly through the URL.

- Eligibility API: Added **deliveryMethods** support to the Eligibility endpoint.

- Timeslot Search: Added **deliveryMethods** to the POST /timeslots/search request body.

- Order Creation: `carrierSelection.carrierCodes` accepts a **deliveryMethod** per carrier on POST /v2/orders and PATCH /v2/orders/{orderId}.

- Eligibility: Added the **sellingPrice** option to `POST /v2/eligibilities` (final selling price per carrier, in `sellingPrice` on each eligibility).

- Deprecation: The **slot option** in the Eligibility v1 API is now deprecated.


## 🛣️ Path-based Versioning
The Retailer API has moved to **URL-based versioning**. All new Version 2 features are now accessed via the `/v2` prefix in the endpoint path, replacing the previous header-based system.

* **Legacy Method:** Required the `x-api-version` header (e.g., `1.17.0`).
* **New Method:** Version is defined directly in the URL (e.g., `https://retailer.last-mile.fr/v2/orders`).
* **Exceptions:** Please note that Click & Collect endpoints—specifically `/collects` remain on the legacy path and do not use the `/v2` prefix.

## 🚚 Delivery Methods Integration
We have integrated `deliveryMethods` across key logistical endpoints to provide more specific control over carrier service levels.

### 1. Eligibility API
The `POST /v2/eligibilities` endpoint includes a `withDeliveryMethods` option in the request parameters.
* **Property:** `options.withDeliveryMethods.active`.
* **Default Value:** This option is set to `true` by default.
* **Response (`true`):** The standard service and each delivery method of a carrier are returned as separate eligibilities. `carrier.deliveryMethod` (code and name) is present on the delivery method ones and absent on the standard service.
* **`false`:** Only the standard service of each carrier is returned.
* **Carrier selection:** `carrierSelection` is not accepted on this endpoint; delivery methods are not filterable in the request.

### 2. Timeslot Search
The `POST /v2/timeslots/search` request body supports `carrierCodes` as an array of strings or of objects.
* **Schema:** `carrierCodeWithDeliveryMethod` (`code`, optional `deliveryMethod`).
* **Standard service:** A code alone (string, or object without `deliveryMethod`) designates the standard service of the carrier only. A delivery method (e.g. "SAMEDAY") must be requested explicitly.
* **Response:** `carrierSlots[].carrier.deliveryMethod` is returned as soon as one item carries a `deliveryMethod` (`null` for the standard service).
* **Error:** A carrier / delivery method pair not eligible for the retailer returns a 403 (`UNKNOWN_CARRIER_CODE`) for the whole request.

### 3. Order Creation and Update
On `POST /v2/orders` and `PATCH /v2/orders/{orderId}`, the `carrierSelection` object allows a `deliveryMethod` for each carrier of `carrierCodes`.
* **`INCLUSION`:** a code alone keeps the carrier with all its delivery methods; an object with `deliveryMethod` keeps only that one.
* **`EXCLUSION`:** a code alone excludes the carrier entirely; an object with `deliveryMethod` excludes only that delivery method.
* **Activation:** Delivery methods are candidates only if at least one item carries a `deliveryMethod`; otherwise only the standard services are considered.
* **`WITHOUT_SHIPMENT`:** only the carrier code is used, `deliveryMethod` is ignored.

## 💶 Selling Price in Eligibility
The `POST /v2/eligibilities` endpoint returns the final selling price of the delivery for the retailer.
* **Option:** `options.sellingPrice.active` (disabled by default) and `options.sellingPrice.timeout` (ms, default `5000`, maximum `10000`).
* **Response:** `sellingPrice` (`taxExcludedAmount`, `taxIncludedAmount`, `taxAmount`, `currency`) on each eligibility, resolved per carrier from the selling grids configured for the retailer. The delivery methods of a same carrier share the same selling price.
* **Difference with `price`:** `price` is the carrier cost, `sellingPrice` is the price at which the retailer sells the delivery.
* **Missing selling price:** a carrier without selling price (no applicable grid, calculation error or timeout) is not returned as eligible. With `options.ineligibleCarriers.active`, it is listed in `ineligibleCarriers` with the reason `technical.incidents.carrier.noSellingPriceAvailable`.
* **`ineligibleCarriers`:** each item carries `carrierName`, `deliveryMethod` (when concerned) and `reasons[]` (`reason`, `message`).

## ⚠️ Deprecations

### Eligibility v1: `slot` Option
The `slot` option within the legacy Eligibility API (v1) is now officially **deprecated**.

* **Recommendation:** Users should migrate to the dedicated `POST /v2/timeslots/search` endpoint for precise, real-time slot management that accounts for carrier constraints and cut-offs.
