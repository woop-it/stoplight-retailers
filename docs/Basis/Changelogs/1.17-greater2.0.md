# Changelog 1.17 -> 2.0


Changes between version 1.17 and version 2.0 are listed here.
Versionning is now in the path with /v2 prefix

- URL-based Versioning: API versioning is now managed directly through the URL.

- Eligibility API: Added **deliveryMethods** support to the Eligibility endpoint.

- Timeslot Search: Added **deliveryMethods** to the POST /timeslots/search request body.

- Order Creation: Added **deliveryMethods** to the POST /orders request body.

- Deprecation: The **slot option** in the Eligibility v1 API is now deprecated.


## 🛣️ Path-based Versioning
The Retailer API has moved to **URL-based versioning**. All new Version 2 features are now accessed via the `/v2` prefix in the endpoint path, replacing the previous header-based system.

* **Legacy Method:** Required the `x-api-version` header (e.g., `1.17.0`).
* **New Method:** Version is defined directly in the URL (e.g., `https://retailer.last-mile.fr/v2/orders`).
* **Exceptions:** Please note that Click & Collect endpoints—specifically `/collects` remain on the legacy path and do not use the `/v2` prefix.

---

## 🚚 Delivery Methods Integration
We have integrated `deliveryMethods` across key logistical endpoints to provide more specific control over carrier service levels.

### 1. Eligibility API
The `POST /v2/eligibilities` endpoint now includes a `withDeliveryMethods` option in the request parameters.
* **Property:** `options.withDeliveryMethods.active`.
* **Default Value:** This option is set to `true` by default.
* **Response:** The API returns specific `deliveryMethod` details (code and name) for each eligible carrier.

### 2. Timeslot Search
The `POST /v2/timeslots/search` request body now supports `carrierCodes` as an array of objects.
* **New Schema:** `carrierCodeWithDeliveryMethod`.
* **Usage:** You can now filter available slots by combining a carrier code with a specific delivery method (e.g., "SAMEDAY").

### 3. Order Creation
When creating an order via `POST /v2/orders`, the `carrierSelection` object now allows you to specify a `deliveryMethod` for each selected carrier.
* **Schema Update:** Added the `deliveryMethod` field to the `carrierSelection.carrierCodes` items.

---

## ⚠️ Deprecations

### Eligibility v1: `slot` Option
The `slot` option within the legacy Eligibility API (v1) is now officially **deprecated**.

* **Recommendation:** Users should migrate to the dedicated `POST /v2/timeslots/search` endpoint for precise, real-time slot management that accounts for carrier constraints and cut-offs.
