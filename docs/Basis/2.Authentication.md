# Authentication

## 🔐 Authentication on Woop 

Access to Woop APIs and services requires strict authentication and authorization. Woop relies on the OAuth 2.0 protocol, using secure Token-based architecture.

All requests sent to Woop API endpoints must include the access token in the HTTP header as follows:
`Authorization: Bearer <access_token>`

The API endpoints used to manage authorizations are as follows, depending on the environment

| Environment   |                            URL                             |
| ------------- | :--------------------------------------------------------: |
| Production    | <https://token.last-mile.fr/oauth/token>          |
| Preproduction | <https://connect.preprod.gcp.last-mile.fr/api/oauth/token> |
| Staging       | <https://connect.recette.gcp.last-mile.fr/api/oauth/token> |
| UAT       | <https://connect.recette.gcp.last-mile.fr/api/oauth/token> |

## 🔄 Token Lifecycle Management at Woop

To ensure uninterrupted service for applications connected to Woop without requiring users to manually re-authenticate, the mechanism relies on access tokens.

### 1. Retrieve credentials and tokens
The application sends its encoded API credentials (client_id and client_secret) to the Woop authentication endpoint: POST /oauth2/token.

The Woop server validates the request (typically using the “Client Credentials” flow) and returns a payload containing the initial access token and the associated refresh token.

<!-- theme: info -->

> 💡 &nbsp; The client_id and client_secret parameters will be provided later by the Woop IT team.

<!-- theme: danger -->

> For this call only, the Content-Type specified in the header must be **application/x-www-form-urlencoded**.

```json http
{
  "method": "post",
  "url": "https://token.last-mile.fr/oauth/token",
  "headers": {
    "Content-Type": "application/x-www-form-urlencoded"
  },
  "body": {
    "client_id": "XXXXXXXXXXXXXXX",
    "client_secret": "XXXXXXXXXXXXXXXX",
    "audience": "https://retailer.last-mile.fr/",
    "grant_type": "client_credentials"
  }
}
```

#### Response

```json json_schema
{
  "type": "object",
  "description": "Token",
  "properties": {
    "access_token": {
      "type": "string",
      "description": "Token to be retrieved and provided in the Header Authorisation"
    },
    "token_type": {
      "type": "string",
      "enum": ["bearer"]
    },
    "expires_in": {
      "type": "number",
      "description": "Token expiration in ms"
    },
    "audience": {
      "type": "string"
    }
  },
  "required": ["access_token", "token_type", "expires_in"]
}
```
### 2. Expiration and Refresh Token Mechanism
The Woop Access Token has a limited lifespan (24 hour / `expires_in": 85999`). As soon as it expires, the application must execute the following cycle:

- Expiration Detection (**401 Error**): A standard API request fails, and the Woop server returns an HTTP 401 Unauthorized status code, indicating that the Access Token is no longer valid.

- Interception and Token Renewal: Your application's HTTP interceptor catches this 401 error, pauses the failed request, and automatically makes a new POST /oauth2/token request to Woop using your stored client credentials to get a fresh token.

- Retry: Once the new token is received, the application updates its configuration and immediately retries the initial request that triggered the 401, making the interruption invisible to the end user.

#### Alternative Strategies for Token Renewal
To handle this lifecycle, you can choose between two main implementation strategies

1 - Client-side refresh_token management (**recommended**)
Instead of waiting for a **401 error**, the client application stores the `expires_in` value locally. Before making any API calls to Woop, it checks whether the token has expired. If the token is about to expire, it requests a new one. This completely prevents failed requests.

2 - Authentication request with every API call
The client application does not store the token long-term. For each operation performed, the application successively sends a `POST /oauth2/token` request to Woop, retrieves the token, and uses it immediately on each endpoint.
