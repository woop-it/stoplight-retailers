## API Versioning Update

### ⚠️ Important Notice: Transition to Path-based Versioning
Starting with **Version 2.0.0** of the Retailer API, we are changing our versioning strategy. To improve clarity and ensure better compatibility with modern API management tools, the versioning is now handled directly within the **URL path**.

### What is changing?

* **Legacy Method (v1.x.x):** Versioning was managed via the `x-api-version` header.
* **New Method (v2.0.0):** The version is now explicitly defined as a prefix in the endpoint path (`/v2/`).

### Comparison

| Feature | Legacy (v1) | Current (v2) |
| :--- | :--- | :--- |
| **Versioning Type** | Header-based (`x-api-version`) | **Path-based (`/v2/`)** |
| **Example Endpoint** | `POST /orders` | `POST /v2/orders` |
| **Status** | Maintenance / Deprecated | **Recommended** |
